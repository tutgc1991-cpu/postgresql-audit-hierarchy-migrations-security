## Objective

This project demonstrates four PostgreSQL database concepts:

1. Trigger-based audit logging
2. Hierarchical data modeling with recursive CTEs
3. Versioned schema migrations using Flyway
4. Least-privilege database security

## Step 1: Audit Logging

An `audit_log` table was created to record changes made to the `students` table.

The audit system records:

* Table name
* Operation
* Old row
* New row
* Database user
* Timestamp

The trigger handles:

* INSERT
* UPDATE
* DELETE

The audit data is stored as JSONB.

## Step 2: Audit Testing

The `students` table was tested with INSERT, UPDATE and DELETE operations.

The audit trail was then queried using JSONB operators.

For example:

```sql
old_row->>'name'
```

and:

```sql
new_row->>'name'
```

These queries show the previous and new values stored by the trigger.

## Step 3: Hierarchical Category Tree

A self-referencing `categories` table was created.

The `parent_id` column references another row in the same table:

```sql
parent_id INT REFERENCES categories(id)
```

The category hierarchy is:

```text
Electronics
├── Computers
│   └── Laptops
└── Phones
```

A recursive CTE was used to walk through the hierarchy and calculate the depth of each category.

## Step 4: Versioned Migrations

Flyway was used to organize and apply database schema changes.

The migration files are:

```text
V1__core_tables.sql
V2__audit_log.sql
V3__categories.sql
```

The migrations are executed in version order.

The Flyway `migrate` command applies pending migrations.

The Flyway `info` command displays migration history and status.

## Step 5: Least-Privilege Security

Two database roles were created:

### app_read

The read role receives:

```text
CONNECT
USAGE
SELECT
```

### app_write

The write role receives:

```text
CONNECT
USAGE
SELECT
INSERT
UPDATE
DELETE
```

The `api` login user is assigned to the `app_write` role.

Sequence permissions were also granted to `app_write` to support generated IDs during INSERT operations.
